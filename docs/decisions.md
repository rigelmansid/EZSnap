### D-1 带 ⌘ 的快捷键由不显示的主菜单分发（2026-10-20，agent 选择）

- 背景：菜单栏应用原来没有主菜单，文字标注框里 ⌘V/⌘C/⌘X/⌘A/⌘Z 全部无效；遮罩和钉图的 ⌘C/⌘S/⌘Z 在 keyDown 里按字符手工判断。
- 选项：A 装不显示的主菜单（文件、编辑），遮罩和钉图实现 copy:/saveDocument:/undo: / B 给文字框做子类，在 performKeyEquivalent 里自己转发编辑命令
- 选择：A
- 理由：macOS 的标准做法，文字编辑命令（含撤销、重做）和快捷键匹配交给系统；只有一处入口，以后加别的文字输入控件不用再补。
- 影响：新加带 ⌘ 的快捷键要在 AppDelegate.makeMainMenu 加菜单项，并在响应者上实现同名方法，不能写在 keyDown（坑 1）；输入文字时 undo: 由 OverlayView 转给字段编辑器。

### D-6 自定义快捷键的做法（2026-10-20，agent 选择）

- 背景：D-3 定了要做自定义快捷键；原来只能从 3 个预设里选，预设按物理键位注册，AZERTY 上 ⌃⌘A 落在标着 Q 的键上。
- 选项：A 弹小窗口录制组合键，保留 3 个预设 / B 只留录制 / C 菜单里多列几个预设
- 选择：A。预设改为按字符定义，注册时按当前键盘布局找键位，切换布局后重新注册；录制期间停用全局快捷键；必须带 ⌘、⌃、⌥ 之一（F1–F20 除外），只带 ⌘ 的不收。
- 理由：录制最直接，预设留给不想设置的人；只带 ⌘ 的组合会把各个应用自己的快捷键（如 ⌘C）全局抢走。
- 影响：自定义快捷键存为键位加修饰键（UserDefaults 的 customHotKey，hotKeyIndex 为 -1 表示用自定义）；录制框要在主菜单之前截下带 ⌘ 的组合（坑 1）。

### D-8 跨屏选区的做法（2026-10-20，agent 选择）

- 背景：D-3 定了要做跨屏选区；原来每块屏的遮罩各管各的选区，一块屏有选区时锁定其他屏。
- 选项：A 选区和标注挪到 CaptureSession 用全局坐标统一管理，各屏遮罩只画自己那部分、把事件转给会话 / B 保留各屏各管各的，由有选区的那块屏转发事件、换算坐标
- 选择：A。拖动可以跨屏；单击横跨两屏的窗口选中整个窗口；导出按涉及屏幕里最高的分辨率拼接，屏幕之间的空隙透明；工具条放在选区右下角所在的屏幕；尺寸标签画在选区左上角所在的屏幕。

- 影响：坐标统一用 CG 全局坐标（主屏左上角为原点）；OverlayView 不再有自己的选区状态；钉图横跨两屏时系统只显示在一块屏上（“显示器具有单独的空间”默认开着）。

### D-11 做 Windows 10 版（2026-10-21，用户决定）

- 背景：用户要一个和 Mac 版功能一样、能在 Windows 10 上安装使用的版本；Mac 版是 Swift + AppKit，不能直接用。
- 选项：技术 A C# + WinForms / B C# + WPF / C C++ Win32；位置 A 同仓库 windows/ / B 另建仓库；验证 A GitHub Actions 的 Windows 机器 / B 用户的 Windows 电脑
- 选择：C# + WinForms，放在同仓库 windows/，用 GitHub Actions 的 Windows 机器编译、跑自检、打安装包（用户选）。目标框架用 .NET Framework 4.8（agent 选择）：.NET 10 官方已不支持普通版 Windows 10，4.8 是 Windows 10 自带的，不用另装运行时。
- 理由：WinForms 的 GDI+ 画法和 AppKit 最接近；这台 Mac 上的 .NET SDK 能编译 net48，但跑不了，只能靠 CI 和用户的电脑验证。
- 影响：Windows 版坐标统一用虚拟屏幕的物理像素（按每屏 DPI 缩放界面尺寸）；⌘ 换成 Ctrl，菜单栏换成托盘，默认快捷键 Ctrl+Alt+A；安装包不签名，会被 SmartScreen 提示。
